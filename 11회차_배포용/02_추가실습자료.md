# 선택 실습 — 배송 운영 대시보드 발전시키기

- 아래 활동 중 **관심 있는 활동을 선택**합니다. 번호는 진행 순서가 아니며, 모두 할 필요는 없습니다.
- 본 강의를 마친 **같은 AI 대화에서 이어갑니다.** 아직 마치지 않았다면 기본 대시보드부터 완성합니다.
- 새 모델을 학습하지 않고, **선정한 모델의 저장된 예측 확률**을 사용합니다.
- 기존 대시보드의 복사본에서 작업합니다. 여러 활동을 하면 같은 복사본에 기능을 이어서 추가합니다.

| 선택활동 | 업무 질문 | 추가할 기능 |
|---|---|---|
| 1. 점검 기준 바꾸기 | 50% 기준의 점검 목록이 너무 적거나 많다면? | 30%·50% 선택과 점검 대상 비교 |
| 2. 점검 순서 바꾸기 | 위험도가 비슷하다면 어떤 주문부터 볼까? | 확률 우선·오늘까지 배송 우선 정렬 |
| 3. 주문 상세 화면 만들기 | 주문을 선택했을 때 무엇을 확인해야 할까? | 주문 상세 정보와 추가 확인 사항 |

## 작업 준비 — 처음 한 번만

~~~text
본 강의에서 만든 results/delivery_operations.html을
results/delivery_operations_extra.html로 복사하고, 추가실습은 복사본에서 진행하자.
이미 복사본이 있으면 덮어쓰지 말고 이어서 작업해줘.
선정 모델과 저장된 예측을 재사용하고, 본 강의의 모델·CSV·HTML은 유지해줘.
새 표는 results/, 인터랙티브 그래프는 results/graphs/에 영문 파일명으로 저장해줘.
~~~

- **공통 자료:** `results/selected_model_11.json`, `results/delivery_operations_11.csv`, `results/delivery_operations.html`.
- **활동 1 추가 자료:** `results/delivery_predictions_11.csv` — 7~8월 평가 결과.
- **기간 구분:** 7~8월은 실제 결과와 비교하는 평가용, 9~10월은 당시의 점검 상황을 재현하는 운영용입니다. 운영 화면에는 실제 배송 결과를 넣지 않습니다.

## 선택 1. 점검 기준을 바꾸면 목록이 어떻게 달라질까?

**목적:** 지연을 더 찾아내는 효과와 늘어나는 점검 물량을 함께 보고, 운영 화면에서 기준을 바꿔봅니다.

### 1단계. 같은 모델의 30%·50% 결과 비교하기

~~~text
[평가 비교]
선정 모델의 delivery_predictions_11.csv 내 지연 확률을 사용해
같은 7~8월 주문에서 30%·50% 기준을 비교해줘. 기준 이상이면 지연 예측이야.
Precision·Recall, 점검 대상 수·TP·FP·FN을 표와 그래프로 보여줘.
지표는 소수 둘째 자리 %로 표시하고, 분모가 0이면 계산 불가로 표시해줘.

[운영 목록]
delivery_operations_11.csv의 최신 점검일에서
기준을 낮춰 새로 포함되는 주문(30% 이상 50% 미만)을 보여줘.
배송여유일수·재고 상태·센터를 함께 보고, 변화와 감수할 점을 짧게 설명해줘.
평가 비교표는 results/threshold_comparison_extra.csv에 저장해줘.
~~~

> **결과에서 볼 점:** 확률은 그대로인데 점검 대상이 어떻게 달라지는지 봅니다. 평가 기간에서 찾아낸 지연과 정상 주문의 추가 점검이 얼마나 늘었는지 확인합니다. 최신일에 새로 포함되는 주문이 없다면 그 자체가 결과입니다.

### 2단계. 대시보드에 점검 기준 선택 추가하기

~~~text
[운영 화면]
delivery_operations_extra.html에 30%·50% 기준 선택을 추가해줘. 기본값은 50%로 하자.
저장된 확률로 점검 대상을 다시 정하고, 선택한 기준을 표시해줘.
기준과 기존 날짜·센터·상품군 필터를 카드·그래프·목록·CSV 다운로드에 함께 적용해줘.

[평가 화면]
모델 검토 탭에 선정 모델의 7~8월 기준별 비교표를 추가해줘.
기존 다섯 모델 비교는 50% 기준으로 유지하고, 운영 화면의 선택과 구분해줘.
기존 기능을 유지하며 데이터·라이브러리가 내장된 같은 복사본에 저장해줘.
~~~

> **결과에서 볼 점:** 기준을 바꾸면 카드뿐 아니라 목록·그래프·다운로드도 함께 바뀌는지 봅니다. 9~10월 위험 주문 수의 증가를 실제 지연 발견 증가로 해석하지 않습니다.

## 선택 2. 같은 점검 대상이라도 확인 순서를 바꿀 수 있을까?

**목적:** 예측 확률과 점검 대상은 그대로 두고, 업무상 긴급도를 반영한 순서를 비교합니다.

### 1단계. 두 가지 점검 순서 비교하기

~~~text
[비교 대상]
delivery_operations_11.csv에서 최신 점검일의 50% 이상 주문을 사용해줘.

[두 가지 정렬]
1. 지연 확률 내림차순 → 배송여유일수 오름차순 → 주문ID순
2. 배송여유일수 0인 주문 우선 → 지연 확률 내림차순 → 배송여유일수·주문ID순
각 방식의 상위 10건을 나란히 보여줘. 대상이 적으면 있는 주문만 보여줘.

상위 목록에 공통으로 들어온 주문과 달라진 주문을 표시하고,
각 정렬이 어떤 업무 목적에 맞는지 짧게 설명해줘.
결과는 results/priority_order_comparison_extra.csv에 저장해줘.
~~~

> **결과에서 볼 점:** 위험 확률을 우선할 때와 오늘 배송할 주문을 우선할 때 상위 목록이 어떻게 달라지는지 봅니다. 10건은 비교용 표시 개수이며 실제 점검 인력의 한도가 아닙니다. 목록이 같다면 다른 날짜를 골라볼 수 있습니다.

### 2단계. 점검 목록에 정렬 방식 선택 추가하기

~~~text
운영 화면의 점검 목록에 '확률 우선'과 '오늘까지 배송 우선' 선택을 추가해줘.
기본값은 확률 우선으로 하고, 앞에서 비교한 정렬 규칙을 사용해줘.
현재 필터와 점검 기준으로 정한 대상 안에서 순서만 바꾸고,
확률·점검 대상 수·요약 카드는 변경하지 말아줘.
CSV 다운로드에도 선택한 정렬을 적용하고, 해당 조건의 전체 점검 대상을 담아줘.
기존 기능을 유지하며 delivery_operations_extra.html에 저장해줘.
~~~

> **결과에서 볼 점:** 순서가 바뀌어도 모델이 계산한 확률과 점검 대상 수는 같습니다. 활동 1도 했다면 선택한 30%·50% 기준의 대상 안에서 순서만 바뀌어야 합니다.

## 선택 3. 주문을 눌렀을 때 담당자에게 필요한 정보 보여주기

**목적:** 점검 목록의 주문 하나를 선택해 현재 상태와 추가로 확인할 내용을 살펴봅니다.

### 1단계. 주문 상세 화면에 담을 정보 정하기

~~~text
운영 데이터의 최신 점검일 점검 목록에서 가장 위의 주문 하나를 예로 들어,
담당자가 확인할 상세 정보를 표로 보여줘. 점검 대상이 없으면 전체 주문 중 확률이 가장 높은 주문을 예시로 쓰고 그렇게 표시해줘.

- 주문ID·점검기준일시·배송약속일·배송여유일수
- 지연 확률·재고 상태·센터·상품군·운송사
현재 데이터에서 확인되는 사실과 업무상 추가로 확인할 사항 1~2개를 구분해줘.
추가 확인 사항은 질문으로 표현하고, 예측 원인이나 지연 확정으로 단정하지 말아줘.
~~~

> **결과에서 볼 점:** ‘재고 미확보’는 데이터에 있는 상태이고, ‘언제 확보될 예정인가?’는 추가 확인할 질문입니다. 실제 상태를 보여주는 것과 모델의 예측 원인을 설명하는 것은 다릅니다.

### 2단계. 주문을 선택하면 상세 정보가 열리도록 만들기

~~~text
운영 화면의 점검 목록에서 주문을 누르면 상세 패널이 열리도록 해줘.
앞에서 정리한 정보와 주문 상태에 맞는 추가 확인 질문을 보여줘.
확인되지 않은 배송 결과나 재고 확보 예정 시각 등은 만들어 넣지 말아줘.

필터나 점검 기준을 바꿔 선택한 주문이 목록에서 빠지면 상세 패널도 닫고,
대상이 없을 때는 빈 목록 안내를 표시해줘.
기존 기능을 유지하며 데이터·라이브러리가 내장된 delivery_operations_extra.html에 저장해줘.
~~~

> **결과에서 볼 점:** 목록과 상세 패널이 같은 주문을 보여주는지 확인합니다. 담당자가 다음에 확인할 사항이 보이되, 예측 확률을 실제 지연 확정으로 오해하지 않도록 구성합니다.
